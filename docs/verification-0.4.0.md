# 0.4.0 自动恢复验证

目标是让明确的格式和布局问题自行恢复，不通过删除证据、放宽引文匹配或把失败裁切标为成功来避免报错。

## 自动处理

1. 规范化明确的页码字符串/单页字段、Fig. N 图号和单段中文图注。引文仍要求精确匹配指定原页。
2. 修复 BOM、JSON 围栏及字符串外的尾逗号。真正损坏的 JSON 保留原文，交给 LLM 最多两次定向修复。截断输出在原 token 预算内精简重试。
3. 正文只返回图号，程序按已核实清单装配全部图注；未知图号、重复图号及遗漏主图仍拒绝。
4. 原图最多三轮重新定位/裁切，最多 8 次视觉请求。仍无法确认时，用相关 PDF 整页代替不完整裁切；可见图注、任务警告、visual-review、figures.json 和 validation.json 均保留未确认标记。
5. 原页预览不写入通过检查点，正常通过的其他图不受影响。传输层临时错误保留原有有限重试；鉴权、永久网络和事实缺失不靠编造内容恢复。

## 验证

- `python -m unittest discover -s tests -q`：72 项通过。新增测试覆盖损坏 JSON、截断、字符串内逗号保留、字段规范化、图注程序装配、未知/重复图拒绝、图片前原页预览标记、鉴权失败和请求预算限制。
- 对真实 Virtual Lab 论文的 22 页原 PDF、6 个阅读检查点和已核对图注做隔离故障注入。模拟图 3 连续三次裁切不通过，文章第一次返回损坏 JSON，第二次返回图号及单字符串导语。
- 结果：任务 completed，复用其他 4 张视觉检查点，图 3 保留第 3、4、5 页整页预览；5 张图及完整中文图注、89 条证据、Markdown/HTML/ZIP 均生成。
- 独立检查 Markdown、HTML 正文及图片一致性、源 PDF SHA-256、整包文件哈希通过；图 3 在来源记录中为 source-pages-fallback、unconfirmed，在校验报告中为 needs_review。
- 模拟共 8 次响应，付费 API 调用 0 次。这验证恢复控制流与文件结果，不代表模型在所有论文上均可正确阅读。

原始成功报告及用户任务数据库未被此隔离测试修改，测试输出仅在 build/recovery-smoke/。
